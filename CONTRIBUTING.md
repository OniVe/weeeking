# Участие в разработке

Спасибо за интерес к Weeeking! Приветствуется любая помощь: сообщения об ошибках, идеи,
улучшение документации и код.

Участвуя в проекте, вы соглашаетесь соблюдать [Кодекс Поведения](CODE_OF_CONDUCT.md).
Об уязвимостях сообщайте приватно по [SECURITY.md](SECURITY.md), а не через публичные issues.

## Сообщить об ошибке

1. Проверьте, нет ли уже похожего issue в трекере.
2. Создайте issue по шаблону «Баг-репорт» и заполните форму: версия и платформа, шаги
   воспроизведения, ожидаемое и фактическое поведение, логи.
3. Не прикладывайте токены и приватные данные — замените их на `***`.

## Предложить идею

Создайте issue по шаблону «Идея / фича» и опишите задачу. Проект — тонкая обёртка над
публичным API Weeek: то, чего нет в API, относится к Weeek, а не к weeeking. Обсуждение до
написания кода помогает сэкономить время — особенно для больших изменений.

## Окружение и тесты

Нужен Rust stable; Python 3 — только для инструментов спецификации.

```bash
git clone https://github.com/OniVe/weeeking.git
cd weeeking
cargo test --locked
```

## Обязательные проверки перед PR

```bash
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
```

CI выполняет эти проверки для Windows и Linux. PR не будет принят, пока они красные.
Для изменений спецификации — `python tools/update_spec.py && cargo fmt` (нужен
`pip install quickjs`; генерация детерминирована).

## Процесс PR

- Одна ветка — одна тема; маленькие сфокусированные PR ревьюить проще.
- Опишите «что и зачем», приложите ссылку на issue (`Closes #123`).
- Для значимых изменений добавьте запись в `CHANGELOG.md` (раздел `[Unreleased]`).
- Обновите README, если изменилось поведение или настройка.
- Переводы строк — LF: это проверяет CI (`.gitattributes`).
- В диффе не должно быть токенов, секретов и приватных данных.
- Сообщения коммитов — короткие, в стиле истории репозитория (на английском).

## Ожидания

- Проект поддерживается на энтузиазме: ответ мейнтейнера может занять несколько дней.
  Если ответа нет больше недели — вежливый ping в треде уместен.
- Обсуждения ведём публично, в issues и PR; приватные каналы — только для безопасности
  и нарушений Кодекса Поведения.
- Если предложение не подходит проекту, issue или PR закроют с объяснением причины —
  это нормальная часть открытого процесса, а не оценка автора.

## Стиль кода

- Форматирование — `cargo fmt`, линт — `cargo clippy` без предупреждений.
- Тесты: unit-тесты в модулях, интеграционные — в `tests/` (mock-сервер, без сети).
- Комментарии — по-русски, как принято в проекте; осмысленные и по делу.
