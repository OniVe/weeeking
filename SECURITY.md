# Политика безопасности

## Поддерживаемые версии

Исправления безопасности выпускаются только для последней опубликованной версии —
обновляйтесь до свежего релиза (`npx -y weeeking`).

| Версия | Поддержка |
| --- | --- |
| Последний релиз | ✅ |
| Более старые | ❌ |

## Как сообщить об уязвимости

Пожалуйста, **не открывайте публичный issue** для уязвимостей.

Используйте приватный канал GitHub: вкладка **Security** → **Report a vulnerability**
(<https://github.com/OniVe/weeeking/security/advisories/new>). Если канал недоступен —
свяжитесь с мейнтейнером [@OniVe](https://github.com/OniVe) через GitHub.

Полезно приложить:

- версию weeeking и платформу;
- шаги воспроизведения (минимальный сценарий);
- влияние: что может сделать атакующий;
- при желании — proof of concept.

Что дальше: подтверждение получения, оценка и исправление в свежем релизе; после публикации
исправления — GitHub Security Advisory (с указанием вашего авторства, если вы не против).

## Область

В охвате — сам сервер weeeking:

- утечка токена (логи, сообщения об ошибках, argv, файлы);
- обход `READ_ONLY=true`;
- инъекции через path/query/body-параметры, включая path traversal при скачивании вложений;
- уязвимости в зависимостях (Rust-крейты, npm-обёртка).

Вне охвата: уязвимости API и сервиса Weeek (сообщайте в Weeek), сторонние MCP-клиенты,
а также атаки, требующие уже скомпрометированной машины.

## Токены

- Токен хранится в системном хранилище или переменных окружения и никогда не попадает в логи.
- Не прикладывайте реальные токены к issue и PR — замените их на `***`.
